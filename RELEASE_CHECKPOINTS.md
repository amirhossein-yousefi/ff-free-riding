# Checkpoint release

This document lists every result-bearing checkpoint behind the paper *Cumulative-Goodness Free-Riding in Forward-Forward Networks: Real, Repairable, but Not Accuracy-Dominant* (NeurIPS 2026), with its source, lineage, size and SHA-256. The machine-readable version is [`release_manifest.json`](release_manifest.json). Each of its entries has an `availability` field, and `_meta.subsets` defines the public and full subsets.

The public release on the Hugging Face Hub (<https://huggingface.co/Amirhossein75/ff-free-riding>) is deliberately minimal. It holds 4 of the 98 files: the seed-42 `stage1_best.pt` of the four central CIFAR-100 arms of main-text Table 3 (γ=0, hardness-gated κ=0, cumulative γ=0.7 and MGC). The other 94 files are available from the author on request (amir.usefi75@gmail.com). Their SHA-256 values below let a recipient verify them. This document also gives the commands used to stage and upload the public release.

## Available on request

- **Scope:** every other row of the [file list](#file-list), marked "on request": 94 files, 53.60 GB. These are:
  - seeds 123/456 of the CIFAR-100 arms;
  - all Stage-2 heads;
  - the CIFAR-10 CP-FAIR, γ=0, gated-ablation, hardness-gated κ=0, MGC-D128 and squared-hinge runs.
- **How to ask:** email the author (amir.usefi75@gmail.com).
- **How they are shared:** `release/stage_release.py --subset full` stages them with the same layout and writes `SHA256SUMS`.
- **All files:** 98 checkpoints, 54.44 GB in total (4 public, 94 on request).
- **Per run:**
  - `stage1_best.pt` is the validation-selected Stage-1 network, including the EMA weights that give the S1 and S1-TTA numbers.
  - `stage2_best.pt` is the Stage-1 network plus the Stage-2 head, which gives S2 and S2-TTA.
  - The `*_last.pt` resume files are not part of the release.
- **Hashing:**
  - SHA-256 over the full file bytes (Python hashlib, 8 MiB chunks).
  - Archive members were streamed from the Google Drive export zips without extraction, and zipfile verified each member's CRC-32.
  - Extracted copies were cross-checked against their archive member's CRC-32.
- **Sources** are given relative to `FF_HOME`, the root of the run archive, which contains `amir-porjects/` and `ff-next/`. `archive.zip::member` names a member of a Google Drive export zip.
- **Loading:** `torch.load(path, map_location='cpu', weights_only=False)` (the four public files also load with `weights_only=True` under PyTorch 2.14.0; `weights_only=False` executes pickle code, so use it only on files whose SHA-256 matches).
  - The dict holds `model`, `net_ema`, `cfg`, the optimizer, scheduler and queue states and, for `stage2_best.pt`, `head_state`.
  - Rebuild the network with the matching trainer and the run's configuration, stored as `cfg` in the checkpoint. See the model card, or `analysis/readouts/s2ff_readout.py` for a minimal example.

## Retraining the Stage-2 probe

When a Stage-1 checkpoint is complete, `trainers/cp_fair_cifar100.py` skips Stage 1 and does two things:

1. It trains only the Stage-2 attentive head: 20 epochs on the frozen EMA backbone, with the same seed-42 train/validation split, which it regenerates from the seed.
2. It runs the final test evaluation (S1, S1-TTA, S2, S2-TTA), written to `events.jsonl` of a new run directory.

This needs a GPU. Put the file under both of its trainer names in `FF_CKPT_DIR`:

- Stage 1 resumes from `<run>_stage1_last.pt`.
- Stage 2 and the final Stage-1 evaluation load `<run>_stage1_best.pt`.

Set `FF_EPOCHS_STAGE1` to the checkpoint's `epoch_stage1` (362 for γ=0 and MGC, 340 for κ=0 and cumulative). Otherwise the trainer resumes Stage-1 training.

```bash
ARM=gamma0;       EP=362; ENV="FF_GAMMA_SCALE=0"
# ARM=gated_k0;   EP=340; ENV="FF_GAMMA_GATING_MODE=adaptive FF_GAMMA_0=0.7 FF_GAMMA_KAPPA=0.0 FF_GAMMA_TAU=1.0"
# ARM=cumulative; EP=340; ENV="FF_GAMMA_SCALE=0.7"
F=ff_cifar100_cifar100_${ARM}_seed42_L4_D256_P2_seed42_stage1_best.pt
huggingface-cli download Amirhossein75/ff-free-riding "checkpoints/c100_trio/$F" --local-dir ./hf
mkdir -p ckpt_s2 && cp "hf/checkpoints/c100_trio/$F" ckpt_s2/ && cp "ckpt_s2/$F" "ckpt_s2/${F/_best/_last}"
env $ENV FF_CKPT_DIR=./ckpt_s2 FF_VERSION_TAG=cifar100_${ARM}_seed42 FF_EPOCHS_STAGE1=$EP \
  FF_NUM_BLOCKS=4 FF_D_MODEL=256 FF_NUM_HEADS=8 FF_USE_SAM=0 FF_N_EXPERTS=1 FF_MOE_TOP_K=1 \
  FF_SEED=42 python trainers/cp_fair_cifar100.py

# MGC (EP=362, the default)
F=ff_cifar100_mgc_c100_L4_D256_P2_seed42_stage1_best.pt
huggingface-cli download Amirhossein75/ff-free-riding "checkpoints/mgc_c100/$F" --local-dir ./hf
mkdir -p ckpt_s2 && cp "hf/checkpoints/mgc_c100/$F" ckpt_s2/ && cp "ckpt_s2/$F" "ckpt_s2/${F/_best/_last}"
FF_CKPT_DIR=./ckpt_s2 FF_VERSION_TAG=mgc_c100 FF_USE_MGC=1 FF_MGC_C0=1.0 FF_N_EXPERTS=1 FF_MOE_TOP_K=1 \
  FF_USE_SAM=0 FF_NUM_HEADS=8 FF_GAMMA_GATING_MODE=constant FF_GAMMA_SCALE=0.7 FF_SEED=42 \
  python trainers/cp_fair_cifar100.py
```

- **Environment:** the per-arm environment is the arm's row of [`repro_manifest.csv`](repro_manifest.csv), with `FF_EPOCHS_STAGE1` set to the selected epoch. The resulting `config.json` equals the original run's, apart from `device`, the camera-ready switches (all off) and, for κ=0 and cumulative, `epochs_stage1`. The regenerated train/validation split equals the run's saved `split_indices.json`. Both were checked on CPU up to the start of Stage 2.
- **Expected numbers:** a retrained head is not bitwise identical to the paper's. The trainer that produced these runs did not store RNG state, so the Stage-2 data order differs. Expect S2 values close to the logged ones, which are in the model card, but not equal to them.

## Staging and upload commands (for the author)

```bash
# 1. stage the 4 public files (copied, SHA-256 verified), README.md (release/MODEL_CARD.md),
#    release_manifest.json and SHA256SUMS
export FF_HOME=/path/to/archive/root          # contains amir-porjects/ and ff-next/
python release/stage_release.py --subset minimal --copy --dest ./hf_release
cd hf_release && sha256sum -c SHA256SUMS && cd ..

# 2. upload (0.85 GB; `upload` creates the model repository if it does not exist)
huggingface-cli login
huggingface-cli upload Amirhossein75/ff-free-riding ./hf_release . --repo-type model \
  --commit-message "Minimal checkpoint release (NeurIPS 2026)"
#    or, from Python:
#    from huggingface_hub import HfApi; api = HfApi()
#    api.create_repo("Amirhossein75/ff-free-riding", repo_type="model", exist_ok=True)
#    api.upload_folder(folder_path="hf_release", repo_id="Amirhossein75/ff-free-riding", repo_type="model")

# 3. verify the upload from a clean directory
huggingface-cli download Amirhossein75/ff-free-riding --repo-type model --local-dir ./hf_check && cd hf_check && sha256sum -c SHA256SUMS
```

Newer `huggingface_hub` releases also provide the `hf` command (`hf upload ...`, same arguments). To share on-request files, stage them with `python release/stage_release.py --subset full --dest ./full_release` (about 55 GB; `--only-group <group>` stages one group), which also copies `preds_cifar100/` to `predictions/` and adds those files to `SHA256SUMS`.
